# 常见问题

### 会不会封号？

**可能会**，没有任何非官方方案能保证不会。SpareDroid 做的是把风险降到最低：

- 用安卓**官方无障碍服务**操作企业微信，和读屏软件是同一套机制；不 root、不 hook、不注入、不改企业微信。
- 只在**被 @ 时**回复，自带频率限制（默认每个群每分钟 6 条、总共 20 条）。
- **不做**群发、自动加好友、自动拉群、批量私信。
- 建议：用专用账号；先在一两个关系好的群里试；别把频率限制调高。

### 为什么不用企业微信官方的机器人？

企业微信的群机器人（webhook）、智能机器人、自建应用都**进不了外部群**（有企业外成员的群）。
官方的「客户群自动回复」只能按关键词回固定内容，接不了 AI，也不能把消息交给你的系统。

### 为什么要一台真手机？云手机 / 模拟器行不行？

可以试，但风险更高：企业微信会检测设备和 IP，云手机常被识别为模拟器、IP 也是机房 IP。
一台几百块的旧手机放在办公室，最稳。

### 能不能用在个人微信？

目前只适配企业微信。个人微信的界面结构不同，且对自动化更敏感，暂不支持。

### 能不能接 GPT / 通义 / 本地模型？

能。`handle()` 就是一个普通 Python 函数，里面调什么都行。仓库自带的 AI 示例用的是 Claude。

### 消息、文件会经过第三方吗？

不会。手机只和**你自己的服务器**通信，代码全部开源。用 AI 示例时，问题和知识库会发给你配置的 AI 服务商。

### 手机为什么要一直亮屏？

无障碍服务操作界面（填字、点发送）需要屏幕亮着、不锁屏。只收消息不需要。
设置方法见 [phone-setup.md](phone-setup.md)。

### 群里同时很多人 @ 它，会乱吗？

不会。每次 @ 都会单独读屏、只处理触发的那一条；指令在手机上排队串行执行。
需要准确对应的场景（比如下单），用 `Reply(..., quote=True)` 引用原消息回复。
